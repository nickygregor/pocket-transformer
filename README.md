# Pocket Transformer

**An inference engine small enough to understand.** A working C++17 CPU runtime for a tiny, byte-level causal transformer, paired with a NumPy reference implementation and trainer.

This is the rebuilt LLM inference **learning project**. The included model is deliberately tiny; it is not a useful general-purpose LLM and its generated text can be repetitive or incoherent.

## Quick start

Requirements: C++17 compiler, Make, Python 3.11+ with a compatible NumPy wheel.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
make
.venv/bin/python train.py --steps 800 --output model.bin
./build/pocket --model model.bin --prompt 'the ' --steps 64
.venv/bin/python quantize.py model.bin model-int8.bin
./build/pocket --model model-int8.bin --prompt 'the ' --steps 64
.venv/bin/python benchmark.py model.bin model-int8.bin
```

On Windows use `.venv/Scripts/python`; adapt Make/compiler invocation. Model files and build outputs are intentionally ignored by Git and reproduced by training. A trained float and int8 model are present in the local workspace.

If macOS reports an SDK/linker mismatch, point your compiler at a compatible installed SDK rather than editing system tools. On the development machine this worked:

```sh
make CXXFLAGS='-std=c++17 -O2 -Wall -Wextra -Wpedantic -isysroot /Library/Developer/CommandLineTools/SDKs/MacOSX15.4.sdk'
```

This is a machine-specific workaround, not a requirement on other systems.

## Model and runtime

- 256 byte tokens; 32 hidden dimensions; 4 attention heads; 64-unit feed-forward layer.
- One pre-normalized causal transformer block with fixed RMS normalization and ReLU.
- Learned token and absolute-position embeddings; 128-byte maximum context.
- Explicit Q/K/V projections, causal softmax attention, residual paths, and output projection.
- KV caching reuses previous attention keys and values during autoregressive decoding.
- `--no-cache` deliberately recomputes the prefix for comparison.
- Greedy sampling by default; `--temperature 0.7 --seed 7` enables seeded sampling.
- JSON output contains text, generated-token count, storage size, and local timing measurements.
- `--logits` emits the last prompt token's logits for reference testing.

Tokenization is raw bytes, not BPE. JSON escapes non-ASCII bytes individually; use ASCII prompts for readable demo output. Prompt bytes plus generated bytes must fit the context. No sliding-window or context extension is implemented.

## Quantization

For each matrix row: `scale = max(abs(row))/127`; store rounded signed int8 values plus a float32 scale. Matrix-vector multiplication reads the int8 weights directly and applies the row scale. Activations and KV cache remain float32. This is weight-only quantization, not integer-only inference.

For this fixed architecture the serialized float model is 114,720 bytes and int8 model is 32,160 bytes. Smaller weight storage does **not** imply faster execution: this scalar CPU implementation may run int8 more slowly. Measure rather than assume.

## Binary format

Little-endian, magic `PTLM0001`, followed by six uint32 fields: hidden size, head count, FFN size, context, vocabulary, quantized flag. Matrices follow in this order:

`embedding, position, q, k, v, out, ff1, ff2, head`

Shapes are defined in `model.py`. Float matrices store row-major float32. Quantized matrices store all row scales followed by row-major signed int8 data. The runtime validates dimensions, finite weights, truncation, and trailing bytes. It does not load GGUF, ONNX, or Hugging Face formats.

## Training

`train.py` implements reverse-mode gradients and Adam in NumPy. `corpus.txt` is a short original educational text bundled under the project license. The seed, steps, corpus size, and training loss are written to `model.bin.json`.

The corpus is intentionally tiny and no held-out quality evaluation is claimed. Training-set loss and throughput are not measures of general reasoning or language capability. Training may overfit this corpus.

## Verify

```sh
.venv/bin/python -m unittest -v
```

Tests compare C++ logits with NumPy, check quantization error and file size, require identical cached/full-prefix greedy output, reject malformed models/context overflow, and validate selected gradients using finite differences.

`benchmark-results.json` records a local sample, not a portable performance guarantee. Rerun `benchmark.py` on your own hardware. KV capacity is reported as an analytical maximum; the implementation grows cache vectors as tokens are processed.

Tiny C++ transformer inference runtime with NumPy training, int8 weight quantization, KV caching, and reference-parity tests.
